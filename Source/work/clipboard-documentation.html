Copy HEX and clipboard feedback

Copy HEX sends the color shown in that row to the clipboard, even if a different key is selected. A single color is copied as an uppercase six-digit value with its leading #, such as #FF58BC. After a successful copy operation, a short message names that exact HEX. Paste into another app or a text field to confirm the result.

If automatic copying is unavailable, a Copy manually dialog opens with the text selected. Press ⌘C on macOS or Ctrl+C on Windows/Linux, then paste where needed. Try again retries automatic copying. Close, Escape or the backdrop dismisses the dialog and restores focus to the original control. The same flow supports multiline Unity C# and JSON export.

Technical behavior

The embedded page may have an opaque origin with no usable Clipboard API. The app first selects a temporary, focusable textarea attached to the document, outside hidden editor sections, and attempts document.execCommand('copy') synchronously during the initiating click. The textarea is removed and prior focus/selection restored. This deprecated API remains a compatibility route for the existing embedded app, not a recommendation for new browser integrations.

If that command does not report success, the app attempts navigator.clipboard.writeText(text). That API requires a secure context and can be denied by browser or embedding permissions. The success message appears only after the selection command returns true or the async write resolves. Rejected or missing APIs open the visible manual dialog instead of claiming success. Older pending requests do not replace newer feedback.

The app does not read the clipboard back or request broader iframe privileges. Feedback reports the browser’s acknowledgement, not an independently verified paste into another application. A manual keyboard copy remains a user action; the dialog does not infer that it succeeded. Copying does not modify color keys, alpha, the selected layer or the preview.
